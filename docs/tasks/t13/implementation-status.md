# T13 — Trạng thái triển khai

Cập nhật: **03/11/2026** · Trạng thái: **Production offline shell, schema resume, quota IDB thật, ACK-waiting preservation, writer-drain guard, Flight-in-flight, lost push response qua cả defer và A→B switch, và hoãn handshake khi tab không phản hồi đã kiểm chứng; còn UI thuộc T14–T23 và nghiệm thu môi trường đích**.

## Đã triển khai

- Production worker precache shell của `/work` và `/milestones` cùng asset graph của build, giữ namespace cache theo build, định tuyến `/` cục bộ tới `/work`, và chỉ dùng response có marker cùng build.
- Account/auth/API/callback/manifest/worker đi network-only; private, no-store, cookie, redirect hoặc response marker sai không được đưa vào shell cache. Flight không tương thích chuyển sang document navigation có giữ URL.
- Build gate chặn hydrate/write khi chưa approved; tab dừng writer qua preparing/switching và có guard revision/epoch.
- IndexedDB schema **1→2** chỉ được nâng trong switching gate có đúng target build/schema/update epoch. Index diagnostics và gate schema checkpoint commit cùng transaction; AES AAD version giữ ở v1 để ciphertext hiện có vẫn giải mã được.
- Runner/config offline tách riêng khỏi dev/production regression, discovery guard được gắn vào verify và CI workflow offline.

## Kiểm chứng đã chạy

- Production offline suite trên Chromium và persistent profile: **6/6 passed** — cold-start `/` sau khi khởi động lại browser offline, API offline bị từ chối, private path không vào Cache Storage, migration gate/checkpoint/rollback, ca tab schema cũ chặn upgrade rồi migration tiếp tục sau khi kết nối cũ đóng, và crash sau khi schema v2 đã commit nhưng trước khi gate duyệt build B. Ca crash đóng browser context rồi mở lại cùng profile; updater hoàn tất switching và draft AES-GCM v1 vẫn giải mã được.
- Production browser regression trên corpus trước khi thêm clock drift spec: **45/45 passed**. Clock drift/jump spec mới: **3/3 passed** trên Chromium dev runner.
- Discovery hiện tại: dev **48**, production **48**, offline **5**; suite thường block service worker và offline suite allow.
- Production build hiện tại đã compile, typecheck và generate đủ hai calendar route; offline service-worker suite chạy trên chính build này và **6/6 passed**.
- `scripts/test-offline-update.cjs`: **1/1 scenario passed** trên cùng origin và browser profile, hiện chạy ba tab — sau khi nạp harness, runner ngắt mạng thật ở BrowserContext rồi tạo hai plan qua `commitLocalMutation`. Một plan được đưa qua `acknowledgePushResponse` với receipt hợp lệ để ở `ack_waiting_pull`; plan kia được gửi bằng coordinator sản phẩm tới API test in-memory. API ghi event rồi giữ phản hồi để mô phỏng mất response khi handshake bị hoãn; lần retry gửi body byte-identical. Lần push kế tiếp cũng được server commit/hold trong lúc build chuyển A→B; build B retry cùng envelope, nhận duplicate receipt và pull đủ hai event. Server test chỉ ghi hai cursor cho hai operation; outbox được gỡ sau pull. Đây là fault-injection API, còn receipt/MySQL thật được kiểm tra riêng ở `pnpm test:sync:browser`. Runner xác nhận trạng thái/hash/ciphertext của operation `ack_waiting_pull` giữ nguyên qua defer và switching. Khi server đã chuyển sang B nhưng gate vẫn chạy A, probe Flight nhận 409 mang marker A và reload trực tiếp vẫn giữ approved build A. Draft chưa lưu ở tab B khiến update bị hoãn; ca tab thứ hai không trả lời message `DAYFORGE_PREPARE_CLIENT` cũng làm handshake timeout, hủy `preparing` và giữ build A. Đây là mô phỏng client không phản hồi ở biên protocol, không phải đo suspend vật lý của browser/OS. Khi `preparing`, test mở tab C mới trước handshake; tab C gia nhập gate và cả ba tab qua `switching` rồi guarded reload sang B. Draft AES-GCM giữ nguyên; quét Cache Storage không thấy owner/title/token/key/note sentinel. Runner ép lỗi asset và quota Cache Storage; build A vẫn approved/cache-ready. Runner chạy hai production build A/B trên một Next server endpoint luân phiên.
- Quota IndexedDB thật được kiểm tra thêm bằng Chromium profile trống dưới quota **256 KiB**: mutation `commitLocalMutation` hợp lệ nhưng lớn (400 dấu mốc, ghi chú lớn) nhận `QuotaExceededError`; revision owner, outbox và projection giữ nguyên. Đây là scenario tách biệt với quota Cache Storage của cài service worker.
- Runner `pnpm test:sync:browser` kiểm chứng offline create/edit/delete theo dependency và reconnect vào MySQL thật; cả hai device hội tụ với operation ID/hash gốc và tombstone xóa. Đây là API/storage harness, chưa phải luồng form trên lịch.
- A/B runner khởi tạo một Flight request có RSC headers khi build B đã waiting, giữ response ở proxy đến khi gate vào `switching`, rồi thả response; browser nhận 409, marker build A và hướng dẫn document navigation. Response không vượt qua build gate.
- Handshake `DAYFORGE_PREPARE_CLIENT` nhận callback `waitUntil`; coordinator abort request đang chạy và chỉ báo drain hoàn tất sau khi vòng sync thoát. Nếu tab được resume trước khi vòng cũ kết thúc, coordinator chờ drain rồi mới mở vòng mới. A/B runner chèn một writer drain delay 750 ms và xác nhận gate vẫn ở `preparing` trước khi drain hoàn tất. Push đồng thời với update chạy qua coordinator sản phẩm và API test in-memory có receipt/pull semantics; MySQL integration được kiểm tra riêng ở sync runner.
- Worker A tiếp tục phục vụ asset A trước khi chấp thuận; worker B chỉ phục vụ asset B trong pha `switching` đúng target/schema. Ca A/B xác nhận bundle B bootstrap được và hoàn tất gate sau guarded reload.

- Biểu mẫu lịch và browser cold-start thao tác nghiệp vụ qua UI vẫn thuộc T14–T23, chưa được suy ra từ harness.
- Tab mới gia nhập giữa `preparing`, draft bẩn hoãn update, client không phản hồi handshake làm update bị hoãn, và crash sau schema commit resume đã chạy. Ca không phản hồi được tiêm qua message listener; chưa thay cho nghiệm thu suspend trên browser/OS đích.
- Chưa nghiệm thu trên HTTPS/browser/OS production target hoặc hoàn thiện runbook nghiệm thu A/B theo môi trường đích.
